Inside Git

Before we start: what Git does

Git keeps a history of your whole project as a series of save points. You can see what changed, go back to an earlier version, and share your work. Nearly every software team uses it.

  • Repository: your project folder plus its history. Git keeps the history in a hidden folder named .git.
  • Commit: a save point. It's a snapshot of all your files, with a message saying what changed and an ID.
  • Two copies: there's one repository on your laptop and one on GitHub. Push sends your commits up to GitHub. Pull brings new commits down.

Who does what: Git is the tool on your laptop that records history. GitHub is a website that stores a copy of your repository. GitHub Pages is the part of GitHub that turns a repository into a live website. Codex runs the Git commands for you and explains them.

Later today, you'll see how branches and pull requests let you try a change safely before it goes live.

3 Create an empty repository on GitHub

Now make the GitHub copy of your repository. You'll make it empty, and Codex will fill it.

Inside Git

The history: a commit is a snapshot with an ID

Codex just made your first commit: a snapshot of your whole project. Its ID is a long string of letters and numbers, usually shortened to the first seven. Each new commit will point back to the one before it, so the commits form a line through time: the history. Right now your history has exactly one commit.

A branch is just a label on a commit. Your project has one label, main, and it's on your only commit.

Inside Git

The snapshot: a tree of names and hashes

Now zoom in on that one commit. It points to a tree: a list of names, each paired with a hash. A hash is a fingerprint of the contents. Change even one letter in a file and its hash changes completely. Each hash leads either to a file's contents or, for a folder, to another tree.

Notice the names live in the tree, not in the files. The file's contents are stored by their hash alone.

A commit's ID is a hash too: the fingerprint of the commit itself, which includes its tree's hash and its parent's hash. Change any file anywhere in the history, and every ID after it changes.

Inside Git

Push copies commits to GitHub

Push copies your commits up to GitHub, then sets GitHub's main label to the same commit as yours.

How often should you commit?

Commit every time you finish one small change that works: a new feature, a bug fix, a style tweak. While you're working, that's often several times an hour. Don't build a whole project and then make one commit at the end.

  • Each commit is a save point. If something breaks, you can see exactly which change caused it and go back to the commit before it. One giant commit gives you only one save point: everything or nothing.
  • Each commit does one thing, and your app still works after it.
  • Write a message that says what changed, like "Add a hint button" or "Fix score not resetting", not "update" or "stuff".
  • Push at least at the end of every work session. Commits on your laptop aren't backed up until they're on GitHub.

Working with Codex? After each change you've tested and are happy with, ask:

5 Deploy with GitHub Pages

Deploying means putting your app on a server so anyone can view it with a browser. GitHub Pages does this for free.

GitHub Pages hosts static websites. It sends your HTML, CSS, JavaScript, and image files to the browser exactly as they are. Your JavaScript runs in the visitor's browser, so games and interactive apps like hangman work fine. But Pages can't run code on a server (like Python or Node.js), and it can't host a database. An app can still save data in the visitor's own browser. Other visitors just won't see it.

Not sure whether your app needs a server? Ask Codex first:

Does this app need a server or a database to work, or can it run on GitHub Pages as a static site?

If your app needs a server or a database: for today, switch to the hangman game (download it here) open a terminal in the hangman folder and start Codex there (as in step 1), then do steps 3–5 with it. That way you still see a deploy work. For the Final Project, look into Netlify or Vercel. They can host apps with a server and a database, and Codex can walk you through how to set that up.

Then ask Codex to deploy:

Turn on GitHub Pages for this repository so it serves the main branch from the top folder. Explain each command before you run it, then give me the address of my live site.

Approve the commands as before. Then open the address Codex gives you. It looks like https://your-username.github.io/your-app/.

Your app running on the web, the same as when you open it on your laptop. The first deploy takes a minute or two. Codex may check on its own that the site is live and tell you when it's ready. If you get a 404 page, wait a minute and reload.

Send the link to someone in your cohort and open theirs. It works on your phone, too.

Inside Git

Pages serves whatever main points to

GitHub Pages watches the main label in your GitHub repository. It takes the snapshot in the commit that main points to, and serves those files as a website. When main moves to a new commit, Pages updates the site on its own. You'll see that happen in Demo 2.

Inside Git

A branch is a second label

Codex made a new label, blue-highlight, and a new commit that points back to the first one. The new label moved to the new commit. main didn't move, so your live site hasn't changed.

Git only stores the files that changed

To make this change, Codex edited two files: style.css (the colors) and index.html (the little icon in the browser tab). Compare the two snapshots:

To save the new snapshot, Git stored only two new files, one new tree, and one new commit. Each changed file is stored as a complete new copy. Each unchanged file is stored only once, however many snapshots include it. Everything else is shared with the first snapshot, including the whole fonts/ and wordlist/ folders: 15 files that weren't copied. Change one file and Git stores one new file. That's why Git can keep thousands of commits without filling up your disk. Git also compresses everything it stores, which saves even more space.

Inside Git

A pull request asks to move main

A pull request is a request to move the main label to include the branch's commit, after a person reads the difference. That person is you today. On a team, it's a teammate. Nothing moves until someone clicks Merge on the pull request.

8 Merge the pull request

On the pull request's page on github.com, click Merge pull request, then Confirm merge.

A purple Merged badge at the top of the pull request.

Inside Git

Merging moves main, and Pages updates

GitHub made one more commit, bae54ec, to record the merge. It points back to both the commit main was on and the branch's commit. Then GitHub moved main to it. Because main moved, Pages starts publishing the new snapshot.

Why use branches if you're working alone?

  • Your live site stays safe. Pages serves whatever main points to. Half-finished or broken work stays on its branch and never reaches your live site until you merge it.
  • You can try ideas you might throw away. If an experiment doesn't work out, delete the branch. main is untouched.
  • You can work on several things at once. Keep each feature on its own branch and switch between them. If you find a bug in the middle of a feature, fix it on a different branch without mixing the two together.
  • You review what the agent did. A pull request shows everything Codex changed in one place, so you read it before it goes live.

9 Switch back to main and pull

Merging on GitHub doesn't change anything on your laptop. Your folder is still on the branch. Codex won't fix this unless you ask, so tell it exactly what you want:

I merged the pull request on GitHub. Switch back to main, pull the latest changes, and delete the old branch. Explain each command before you run it.

Inside Git

Two repositories, two main labels

There are two copies of your repository: one on your laptop and one on GitHub. Each has its own main label. Merging on GitHub moved only GitHub's label. Before you pulled, they looked like this:

Pull is the mirror of push. It copies the new commits down from GitHub and moves your laptop's main label to match. After the pull, your laptop looks just like GitHub. Switching to main first makes sure your folder shows the files from the snapshot main points to.

Troubleshooting

When a Git or GitHub command fails, start by asking Codex:

That command failed. Explain what the error means in plain words, then help me fix it. Explain each command before you run it.
git, gh, or codex isn't found
Finish the setup page. On Windows, close PowerShell and open a new window after installing anything.
Codex says it can't write to .git, or it can't make a commit
Do step 2: type /permissions in Codex.
The push was rejected
Your GitHub repository probably isn't empty. That happens if a README, .gitignore, or license was added when you created it. Ask Codex for help using the prompt above. Or delete the repository on github.com (Settings, then the bottom of the page) and redo step 3 with everything left off.
GitHub says you aren't logged in, or asks for a password
Run gh auth login again, as on the setup page. Then retry.
Your live site shows a 404 page
Wait a minute or two and reload. If it still fails, check that the repository is Public, and that index.html is at the top of your repository on github.com, not inside another folder.
Your app doesn't have an index.html, or it needs a build step to run
Some apps (for example, ones made with React or Vite) have to be built before they can be deployed. Ask Codex: "How do I deploy this app to GitHub Pages? Explain each step before you do it."
Your live site still shows the old version
Wait a minute, then reload while holding Shift. On github.com, the Actions tab shows whether Pages has finished publishing.
Your app on your laptop shows the wrong version
Your browser shows whatever branch your folder is on. Ask Codex: "Which branch am I on?"
The hangman zip won't open properly on Windows
Right-click the zip and choose Extract all, then use the extracted folder.
