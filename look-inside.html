Look inside Git

← Back to class Git's objects Labels Other places to deploy

For the curious. The "Inside Git" boxes in class described commits, trees, hashes, and labels. These commands show you the real ones in your own repository. Run them in a terminal in your app's folder. They only read, so they can't break anything.

Commands with a ' quote mark work as written on both Mac and Windows. Type q to leave any output that fills the screen.

Git's objects

The history

See every commit, newest first, with lines showing how they connect:

git log --oneline --graph --all

After Demo 2, you'll see the fork and the merge from the drawings in class.

A commit

Print the commit that main points to:

git cat-file -p main

A commit is a short piece of text. It has a tree line (its snapshot), a parent line for each commit before it (a merge commit has two), your name and the time, and the message. The commit's ID is the hash of exactly this text. That's why your commit IDs differ from the instructor's, even for the same files.

A tree

Print the snapshot's top-level tree:

git cat-file -p 'main^{tree}'

Each line is a type (blob for a file's contents, tree for a folder), a hash, and a name. To open a folder's tree, put its name after a colon:

git cat-file -p 'main:fonts'

A file's contents, by hash

Copy any blob hash from the tree and print what it stores. Paste your hash in place of the one below; the first seven characters are enough.

git cat-file -p 7b58897

A hash is a fingerprint

Ask Git to compute the hash of a file on your laptop, without storing anything:

git hash-object style.css

It matches the hash for style.css in the tree, as long as you haven't changed the file since your last commit. Change one character, run it again, and the hash is completely different. Using the hangman game? Your file hashes match the instructor's exactly, on any computer.

Compare two snapshots

After Demo 2, compare the tree from before the change with the tree after it. (main~1 means "the commit before main".)

git cat-file -p 'main~1^{tree}'
git cat-file -p 'main^{tree}'

Only the files that changed have new hashes. Every other line is identical, because both snapshots share those objects.

Labels

A branch really is just a label. Git stores it as a tiny file that holds a single commit ID:

cat .git/refs/heads/main

If that file isn't there, Git has packed its labels into one file. This command asks Git directly:

git rev-parse main

Your laptop also remembers where GitHub's main was the last time you pushed or pulled. It calls that label origin/main. Compare the two:

git rev-parse main origin/main

Right after a push or pull, the two IDs are the same.

Which branch is your folder on right now? Git keeps that in one more small file:

cat .git/HEAD

Other places to deploy

GitHub Pages is one of many places to put a website. Netlify and Vercel also host sites for free. They can deploy straight from a GitHub repository, and they also run apps that need a build step, like ones made with React. The idea is the same: when main moves, your site updates.
